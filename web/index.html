Why this is not just a hash on a chain

    
The usual design anchors a daily summary, which cannot prove anything about one decision.

    

      A rebalance screens ~500 companies; this run holds 53,384 records. One transaction each prices
      per-decision proof out of existence. Batching into a tree makes a single decision provable in
      log₂(n) hashes — 16 here — against a chain that stores one 32-byte root.
    

    

      Only the root, the config hash and a count go on chain. No company data, no holdings, no personal
      data. This proves a decision existed, unchanged, at a given block, under a named version of the
      rules. It deliberately proves nothing about whether the decision was any good.
